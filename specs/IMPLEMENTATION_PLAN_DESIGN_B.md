# Implementation Plan: Design B Locked Shadow Tree

## Scope

Replace fixed hero fields with generic native widget Content and Style editing.
The parent remains authoritative for element existence, type, parentage, order,
and container settings. Consumer pages persist a locked derived shadow tree plus
sparse widget-control overrides.

## Module boundaries

### Purpose

- `EC_Component_Shadow_Sync`: reconcile current parent data, source/runtime IDs,
  sparse overrides, and a derived locked shadow tree.
- `EC_Component_Instance_Widget`: host real nested Elementor child models and
  render them through Elementor's native element pipeline.
- `assets/editor.js`: hydrate shadows, mirror native setting changes into sparse
  intent, hide forbidden controls, and block structural commands.

### Callers

- Elementor's widget registry creates the Component Instance widget.
- Elementor document save filtering validates and reconciles consumer data.
- The editor requests a current shadow snapshot through authenticated AJAX.
- Parent document saves fan out reconciliation to indexed consumers.

### Contracts

- Parent `_elementor_data` is never mutated by instance editing.
- Every shadow node has a consumer-unique runtime ID and stable parent source ID.
- All shadow containers and widgets are structurally locked.
- Only current widget Content and Style controls can enter sparse overrides.
- Presence, including an empty value, means override; absence means inherit.
- Missing parent widgets and controls are ignored and pruned.
- Consumer page CSS is generated by Elementor from real shadow models.

## Dependencies

- `[OK]` Elementor 4.1.5 existing nested-element and command-hook APIs.
- No new packages.

## Success criteria

1. Generic sparse reconciliation preserves explicit empty values, inheritance,
   parent updates, source identity, and immutability → verify:
   `php tests/component-shadow-sync-test.php`
2. Component Instance uses `Widget_Nested_Base`, serializes locked native child
   models, and no longer registers fixed hero fields → verify:
   `php tests/component-instance-contract-test.php`
3. Editor hydration and command guards are syntactically valid and cover create,
   delete, duplicate, and move → verify: `node --check assets/editor.js`
4. Existing regression behavior stays green during migration → verify:
   `php tests/component-overrides-test.php`
5. All touched PHP and JavaScript files have no blocking diagnostics → verify:
   `lsp_diagnostics` and `lens_diagnostics mode=all`
6. Elementor 4.1.5 runtime creates native nested children and independent page
   CSS → verify with the Local WordPress runtime harness documented in
   `specs/archive/spikes/SPIKE-design-b-shadow-tree.md`
7. Browser behavior covers selection, Content/Style, reset, locks, two instances,
   carousel descendants, parent updates, undo/redo, and reload → verify manually
   with `tests/design-b-browser-matrix.md`.

## Steps

4. Add authenticated shadow hydration, save filtering, consumer indexing, and
   parent-save reconciliation → verify: `php tests/component-shadow-sync-test.php`
5. Add editor hydration, live sparse-intent capture, panel filtering, and
   structural command guards → verify: `node --check assets/editor.js`
6. Run all mechanical gates and record browser cases → verify:
   `php tests/component-shadow-sync-test.php && php tests/component-instance-contract-test.php && php tests/component-overrides-test.php && node --check assets/editor.js`

## Out of scope

- Supporting Elementor versions other than 4.1.5.
- Eager queues or custom database tables for very large consumer counts.
- Guaranteeing undocumented third-party control views before browser testing.
- Instance changes to container settings or element structure.

## Risk

**P0:** private Elementor editor APIs, cross-document synchronization, and saved
page data integrity. PHP reconciliation is the final trust boundary; JavaScript
locking alone is never treated as authorization or persistence validation.
